# ADG RMM Roadmap

ADG RMM is becoming an all-in-one MSP platform: RMM, PSA, documentation, billing and client-facing tools in one product.

Last updated: 2026-11-20. For what exists today, in detail, see [FEATURE-STATUS.md](FEATURE-STATUS.md).

## Status key

| Mark | Meaning |
|---|---|
| ✅ | **Done:** built and confirmed working on a real machine or in real use |
| 🧪 | **Needs testing:** built and deployed, not yet confirmed on a real machine |
| 🟡 | **Partial:** some of it works, and the rest is missing |
| 🔴 | **Broken or fake:** known not to work, or a screen that only looks like it does |
| ⬜ | **Not started** |
| ⛔ | **Blocked:** waiting on an outside decision or action, named in the step |
| ➖ | **Decided against:** will not be built |

Update the mark on a step when it changes. A phase is only ✅ once every step in it is ✅.

**Current focus (updated 2026-11-13):** getting ADG RMM ready for other people to install and use. The all-in-one installer is built and tested (10.17), the client portal (Phase 5) is built, and the dashboard no longer caps at 1000 devices (1.40). Next: use the installer on real machines, finish the leftovers listed under 1.41 and 10.21, then the unwired admin screens (Phase 2) and the service desk gaps (Phase 3). Remote connection work (1.18 onward) continues after that.

**On hold:** workflows and most integrations (Phase 9), and the parked remote-connection item 1.22f (virtual display, which also waits on a licensing decision). 1.24 (a different video engine) was tried and decided against. Billing (Phase 4) and documentation (Phase 6) are live but untested.

## Suggested build order

Each step builds on the one before it, and each one is useful alone.

1. ⬜ **Alerts and notifications** (1.1–1.4): the product starts telling you about problems.
2. ⬜ **Hide or finish fake admin screens** (2.1), and **audit log** (2.2): the product stops misleading people, and every later feature can record what it does.
3. ⬜ **Checks and scripts** (1.5–1.8): technicians can set up monitoring and automate from the dashboard.
4. ⬜ **Security items** (10.1–10.6): closes known risks before more customers depend on it.
5. ⬜ **Patching and maintenance windows** (1.9–1.11).
6. ⬜ **Service desk** (Phase 3).
7. ⬜ **Time, contracts and billing** (Phase 4): the product can run the business side.
8. ⬜ **Client portal, documentation, reporting** (Phases 5–7).
9. ⬜ **Security services, integrations, release** (Phases 8–10).
